# API contracts

Base path: /api/v1. docs/openapi.json is generated by node scripts/openapi.mjs and served at /api/v1/openapi.json. It provides the registered route inventory, security requirements and core request schemas. Extended writes also reference the authoritative shared Zod schemas or local route schemas below; generic OpenAPI object entries are not an exhaustive field contract.

## Authentication and command rules

Merchant/operator cookies use innovia_session. Browser authenticated writes require X-CSRF-Token from the login/me response. Customer cookies are boutique-specific; native register/login with client=native returns a bearer token that is scoped to that boutique. Origin checks apply to browser writes. A client-supplied tenant ID never grants access.

Financial, inventory, duplication, bulk-price, invitation, campaign and fitting commands require Idempotency-Key: 8–100 letters/digits/underscores/hyphens. Retry an uncertain request using the same key and payload. Reusing a key with another payload conflicts. Shared clients preserve uncertain retry keys. Errors return error.code/message/details; money is returned as decimal strings.

Rate-limit rejections return HTTP 429 with `error.code=RATE_LIMITED`, a readable JSON `error.message`, `Retry-After` in seconds and standard rate-limit headers. Global and endpoint-specific limits use the same response contract. Respect the retry delay; an unconfirmed financial request still needs its original idempotency key when retried.

## Public boutique and customer APIs

Public /storefront discovers active boutiques. /storefront/:slug resolves branding/published content, storefront stores and policies. /products supports q, category, collection, brand, size, color, minPrice, maxPrice, page, limit and sort=newest|name|price_asc|price_desc. Variant filters must match the same variant. /facets returns real active-catalog choices. /products/:id returns public fields without internal costs.

Public POST /products/:id/size-advisor accepts at least one positive cm measurement: chest, waist, length (max 300) or footLength (max 60). It compares only the product's published chart and returns recommendation, alternative, measurement differences, availability, optional brand-provided size equivalents, explanation and basis. Missing chart measurements return no recommendation or SIZE_CHART; input is not persisted. GET /products/:id/ar returns disabled/fallback status unless a licensed product lens, feature entitlement and approved provider are configured. Its browser token is origin-restricted, not a backend secret.

POST /storefront/:slug/checkout supports guest or authenticated pickup/COD using checkoutSchema. Stock, prices, discount, rewards, delivery/tax and customer ownership are checked server-side. Tracking requires the order number and private tracking token. Retail card checkout is not available.

Customer routes under /storefront/:slug/customer include register/login/me/logout/profile, addresses, orders, wishlist, consents/preferences, loyalty/enroll/redeem, notifications, export and account deletion. Recovery request/reset are public but boutique-bound. Recovery requests return the same 202 message for existing/missing accounts; tokens expire after one hour and revoke prior sessions on use.

Customer /media accepts private raw images with X-Photo-Consent=self-photo-v1; private image reads require the owner. /try-on commands require the current explicit processing consent/version and configured credits/provider. Jobs are polled, private, expiring and deletable. /push/devices POST/DELETE registers/disables the authenticated customer's Expo token; registration returns 503 when push is unconfigured.

Media storage can be local or private S3 without changing these API contracts. Unconfirmed/failed uploads are hidden; public uploads return their managed API URL only after storage confirmation. Private photos use `no-store`, expire after 24 hours and remain inaccessible while physical cleanup is pending. Temporary photos are excluded from new encrypted backups. A provider outage returns an error and preserves a retryable cleanup record. See [STORAGE.md](STORAGE.md) for configuration, migration, quotas and retention boundaries.

## Platform and integration hooks

Platform overview/plans/workspaces/billing/support routes administer merchants, subscriptions and manually reconciled invoices. /platform/control exposes scoped operator tools for stores, operators, feature/usage limits, audits and provider readiness; it never returns provider secrets. Plan reductions that conflict with current usage are rejected/reviewed.

POST /billing/stripe/webhook requires the exact raw JSON and valid Stripe-Signature. Verified amount/currency/event idempotency precede invoice activation. Recurring enrollment also requires consent=monthly-renewal-v1 and a planId with Idempotency-Key. Cancellation requires confirmed=true. Signed monthly invoices are bound to their saved subscription and line-item service period; Checkout completion alone grants no access. Uncertain provider submissions older than 23 hours require reconciliation. It does not process merchant retail orders. Optional Fal, Resend, Expo and Snap behavior is documented in DEPLOYMENT.md; missing credentials never cause fake provider success.
